Follow these steps in order. You will create one authored test page containing 22 numbered examples, run it with sample API data, edit the author controls, and test both response formats and failure handling.

Step 1 — Keep both local servers running

  1. Start your AEM server from the etrade repository on et-dynamic: npx -y @adobe/aem-cli up. Its usual address is localhost:3000/home.
  2. In a second terminal, start the rate test helper: npm run demo:rates. This guide and its sample API run on 127.0.0.1:3020. Keep both servers running. Use Node.js 22.7 or newer for the helper and automated tests.
  3. Open the complete working showcase. The summary should read 22/22 examples match and Rate requests: 1.
  4. Open the card regression checks. Expect 24/24 checks passed for empty rows, extra cells, rich text, independent binding names and numeric or placeholder fallbacks.

Why two addresses? Port 3000 loads your previewed DA content. Port 3020 reads that content through port 3000 and supplies the sample rates on the same local address. This lets you test authored API cards while access to the live E*TRADE endpoint is unresolved. The helper adds a rate inspector at the bottom of authored pages.

Test a dummy user balance

On the page you are testing, open the browser console and set userBalance in localStorage, then reload:

localStorage.setItem('userBalance', '100000');
location.reload();

Use a plain non-negative decimal without commas or a currency symbol. This works on localhost, 127.0.0.1, IPv6 loopback and aem.page preview hosts. Storage is separate for every origin, including port: set it on the same page you are testing. The local showcase also has an Apply balance control.

Savings and checking API bindings, including hybrid bindings with empty Override, use the dummy balance to select their JSON tier. This is client-side selection; the dummy balance is not sent to the rate endpoint. Manual rates, populated hybrid overrides, CD terms and ordinary authored copy keep their values. Production hosts, including aem.live, ignore this key.

Settings reference

SettingValues
NameOptional, defaults to rate. A unique name per binding within its row; letters, numbers and hyphens, starting with a letter.
ModeRequired: api, manual or hybrid. API ignores Override; manual requires Override; hybrid uses it only when populated.
Product3100 = Premium Savings; 4240 = Max-Rate Checking; 3500 = CD.
FieldadvertisedAPY, disclosureAPY or finalRate. CDs also support minDisclosureAPY and maxDisclosureAPY. CD responses have no advertisedAPY field.
BalanceRequired for savings/checking API bindings. Plain non-negative decimal; no commas or currency symbols.
TermRequired for a CD tier. Sample terms: 6M, 9M, 12M, 18M, 24M, 36M, 60M. Omit Term and Balance when using the CD calculated minimum/maximum fields.
OverridePlain non-negative decimal, without %. 0 is valid.
FallbackOptional plain non-negative decimal, without %, or the display placeholder -.--. With Fallback: -.--, valid API/hybrid cards still request rates and show the placeholder while loading or when a rate cannot be resolved. Keep % and APY authored beside the marker. An omitted fallback displays — when data cannot be resolved.

Supported blocks: cards-product, cards-account and cards-pricing. Add one Rate settings cell for each distinct named value. Repeated markers in a row share that binding. Existing ordinary cards do not need settings.

Automated checks: npm run test:rates and npm run lint. The local showcase validates displayed values, sources, error states, API retrieval timestamps and request counts. Docs, local test fixtures and the inspector are excluded from AEM delivery; the dummy JSON files under /phx/pros/ are included for branch testing. The production blocks do not import this test helper.
