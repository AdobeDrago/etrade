Your first E*TRADE edit

Learn how to draft a page in Adobe Document Authoring, work with E*TRADE blocks and disclosures, and review your changes before publishing.

Get oriented in DA

Open the E*TRADE content workspace to browse pages, shared fragments, and sheets. In the editor, use Layout for a visual view, Content to see the source structure, or Split to see both.

DA stores content. GitHub supplies the code that renders it. An editor ref such as ?ref=demo selects code while using the same DA content across branches.

Start with a reviewed page

For practice, copy the closest reviewed page to an agreed, unused draft path. For a routine edit, open the existing page and locate the section or block you own.

Review inherited copy, assets, destinations, metadata, and legal dependencies. Confirm which pieces are shared before editing them.

Edit a block table

The merged first row names the block. Use the catalog to find its exact name, supported options, and required cells. A Cards Article table, for example, uses one complete row per card.

Keep one page H1, give informative images meaningful alt text, and put a CTA in its own linked paragraph where the block expects an action.

Find a block in the catalog

Set page and section metadata

Use the page Metadata table for Title, Description, Image, Theme, and Disclosures. Put Section Metadata in the section it configures.

Theme selects Purple or Charcoal. Section Color Scheme selects light or dark. Grid arranges whole blocks inside a section.

Check shared content and disclosures

Navigation, footer, and reusable fragments can feed multiple pages. Edit the shared source when the change should reach its consumers, then review those pages.

For ID-based disclosures, select the approved set in page metadata. Superscript the stable ID after the claim, such as offer. Use Disclosure Manager when available and verify every marker against the rendered footer.

Review fragments and disclosure references

Preserve link and rate settings

Keep campaign parameters and tracking markers when editing destinations. If Link Options is enabled, open it from Outline → Extensions to inspect a selected link or prepare a URL.

For a dynamic rate, keep the marker, such as {{rate:base}}, and its separate Rate settings cell in the same row. Review the rendered rate, units, and approved terms together.

Preview and review

Save the page and any changed dependencies. In Experience Workspace, open Send → Preview and choose Update. Check the resulting .aem.page URL on the intended code branch.

Review phone and desktop layouts, keyboard access, headings, image crops and alt text, final link destinations, rate state, and the complete legal footer.

See the preview and release workflow

Publish and verify

After the required approvals and code deployment, publish changed shared fragments, disclosure sources, and target pages before the pages or navigation that reference them.

Use Preview & Publish → Update for the page. Open its live URL, follow a real entry link, and verify the approved content and disclosures.
