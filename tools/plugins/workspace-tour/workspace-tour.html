Try the design system

Example In the style showroom, switch Page family from Purple to Charcoal, then set a dark Section scheme and two Blocks per row. Narrow the window to see how the grid adapts.

Try the funding calculator

Widget Calculator turns authored funding and cash-credit tiers into an interactive brokerage offer. It calculates from the configured tiers in the browser. Promo code, eligibility text, links, and disclosures come from the page.

Example On Home, choose the highest funding tier using the desktop slider. Switch to a phone width and check that the dropdown shows the same open-ended range and credit.

See how bank rates resolve

Supported cards, account tabs, and FAQs can pull selected savings, checking, or CD rates. A rate binding can use the approved service, a manual value, or a manual override with service lookup when the override is empty. The page supplies the units and terms.

Example On a demo page with a balance-based savings rate, use Demo controls → Page tools to try two test balances. Check the rate result and then restore the authored balance. The override is local to the demo.

Example On Welcome Back, switch Top Five from stocks to ETFs. Check that the symbols, charts, and disclaimer change together and that sample data is labeled.

Review privacy and link tracking

The footer’s Your Privacy Choices action opens OneTrust preferences where the SDK is configured. The demo cookie banner can be reviewed on preview with ?cookiebanner=true. Authored tracking events wait for their required consent categories. Production delivery requires a connected sender.

Example In Demo controls → Tracking, use a sample click to compare a pending event with an event eligible to send after simulated consent. Review actual page clicks in their separate queue.

Inspect links with Link Options

Link Options reads a selected link or a pasted destination. It can set a tracking key and consent categories, configure a path-specific label and destination, or turn a link into a cookie preferences action. Supported Canvas selections can be updated directly. Copy URL also works for manual editing.

Example In the Link Options demo, enable a rule for /brokerage. Compare the result for /brokerage/learn with the default link on /home.

Review and reorder disclosures

Disclosure Manager loads the page’s ID-based set, audits references in saved content, previews the legal footer, and can insert a reference at the cursor. Reordering changes the display numbers while preserving each disclosure’s stable ID.

Example Open the Disclosure Manager demo and move a disclosure up. Compare the new footer numbers with the stable IDs in the disclosure list.

Move content with Import & Export

Import & Export can download saved DA source as page XML and review supported XML or XHTML before import. The default creates a new page. Replacing the current page uses a comparison and confirmation. An advanced demo imports sample product XML into Adobe Structured Content and exports it back to XML.

Example In the Import & Export demo, choose Try page sample, review its sections and metadata, and download the resulting DA HTML.

Get oriented in DA

Open the E*TRADE content workspace to browse pages, shared fragments, and sheets. In the editor, use Layout for a visual view, Content to see the source structure, or Split to see both.

DA stores content. GitHub supplies the code that renders it. An editor ref such as ?ref=demo selects code while using the same DA content across branches.

Example Open Home with ?ref=demo and switch to Split. Find the Hero Dark table in the content pane and compare its headline with the rendered hero.

Start with a reviewed page

For practice, copy the closest reviewed page to an agreed, unused draft path. For a routine edit, open the existing page and locate the section or block you own.

Review inherited copy, assets, destinations, metadata, and legal dependencies. Confirm which pieces are shared before editing them.

Example Copy /planning to an unused draft path such as /drafts/planning-review. Review the inherited title, social image, and offer links before adding your approved copy.

Edit a block table

The merged first row names the block. Use the catalog to find its exact name, supported options, and required cells. A Cards Article table, for example, uses one complete row per card.

Keep one page H1, give informative images meaningful alt text, and put a CTA in its own linked paragraph where the block expects an action.

Example In a Cards Article row, put the image and its alt text in the left cell. In the right cell, add “Plan for retirement” as an H3, supporting copy, and a “Read the guide” link in its own paragraph.

Find a block in the catalog

Set page and section metadata

Use the page Metadata table for Title, Description, Image, Theme, and Disclosures. Put Section Metadata in the section it configures.

Theme selects Purple or Charcoal. Section Color Scheme selects light or dark. Grid arranges whole blocks inside a section.

Example Set Theme: Purple in page Metadata. To place two blocks side by side in a dark section at desktop widths, add Color Scheme: dark and Grid: 2 to that section’s Section Metadata.

Look up metadata fields and values

Check shared content and disclosures

Navigation, footer, and reusable fragments can feed multiple pages. Edit the shared source when the change should reach its consumers, then review those pages.

For ID-based disclosures, select the approved set in page metadata. Superscript the stable ID after the claim, such as offer. Use Disclosure Manager when available and verify every marker against the rendered footer.

Example If the selected set contains offer, put that ID in superscript after the approved claim. In preview, follow the displayed number to #disclosure-offer and confirm that it opens the matching terms.

Review fragments and disclosure references

Preserve link and rate settings

Keep campaign parameters and tracking markers when editing destinations. If Link Options is enabled, open it from Outline → Extensions to inspect a selected link or prepare a URL.

For a dynamic rate, keep the marker, such as {{rate:base}}, and its separate Rate settings cell in the same row. Review the rendered rate, units, and approved terms together.

Example In a savings card, pair {{rate:base}}% APY with Name: base in the Rate settings cell. If you relabel its CTA, preserve destination parameters such as icid=campaign and @tracking=savings-card.

Preview and review

Save the page and any changed dependencies. In Experience Workspace, open Send → Preview and choose Update. Check the resulting .aem.page URL on the intended code branch.

Review phone and desktop layouts, keyboard access, headings, image crops and alt text, final link destinations, rate state, and the complete legal footer.

Example In the Planning draft preview, check the hero image crop at phone width. Then press Tab to reach the primary action and Enter to confirm that it opens the intended page.

See the preview and release workflow

Publish and verify

After the required approvals and code deployment, publish changed shared fragments, disclosure sources, and target pages before the pages or navigation that reference them.

Use Preview & Publish → Update for the page. Open its live URL, follow a real entry link, and verify the approved content and disclosures.

Example If an approved Planning update changes a legal fragment, publish that fragment first, then its disclosure set if it changed, and finally /planning. Open Planning from the live navigation and follow the disclosure marker to the updated terms.
